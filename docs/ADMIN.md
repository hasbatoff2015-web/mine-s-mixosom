# Закрытый доступ двух администраторов

Игровой сервер и админка — разные входы. Ник, `/op`, `FC_OPERATORS` и игровой `sessionToken` администратором не делают. Права у двух человек одинаковые. Секреты разные. Кто именно вошёл, видно по его id.

Админский HTTP не висит на публичном порте игры. Отдельный слушатель в том же процессе принимает соединения только с `127.0.0.1`. Снаружи его не открывают. Заход с компьютера администратора — SSH-туннель на этот loopback.

Пока `FC_ADMIN_PORT` не задан, слушателя нет. Игра стартует как раньше.

## 1. `FC_ADMIN_IDS`

Ровно два разных id, через запятую. Это не пароли и не ники игроков.

```bash
FC_ADMIN_IDS=admin-owner,admin-colleague
```

Пустое или отсутствующее значение выключает админские действия. Один id, три id, повтор и пробел в id сервер не примет. Оба id имеют одинаковые права. Отдельного суперадмина нет.

## 2. Два секрета

На своём компьютере, не на игровом сервере и не в репозитории:

```bash
npm run admin:provision -- admin-owner admin-colleague
```

Скрипт печатает два случайных токена по 32 байта и строку `FC_ADMIN_AUTH_HASHES`. Файл он не пишет.

Токен владельца передайте только владельцу. Токен коллеги — только коллеге. Устно, через менеджер паролей или другой закрытый канал. В чат, в git и в сейв мира их не кладут. В обычный лог сервера они не попадают.

## 3. Хэши на сервере

В приватный env процесса, например `/etc/frontier-cubes/anarchy.env`, попадают только хэши:

```bash
FC_ADMIN_IDS=admin-owner,admin-colleague
FC_ADMIN_AUTH_HASHES=admin-owner:<64 hex>,admin-colleague:<64 hex>
```

Подставьте строку из вывода скрипта. Сами токены в env не пишите. В git эта строка не коммитится. Шаблоны в `deploy/systemd/*.env` оставляют эти переменные закомментированными.

Хэш пустой строки сервер отвергает. Два одинаковых хэша тоже. Если хэша нет хотя бы у одного id, админский порт не поднимется.

## 4. Приватный порт

```bash
FC_ADMIN_PORT=8765
```

Слушатель всегда на `127.0.0.1`, даже если игровой `HOST=0.0.0.0`. Порт в файрволе не открывать.

Три режима — три процесса. Каждому свой порт, если админка нужна на этом процессе:

| Процесс | Пример порта |
| --- | --- |
| Anarchy | `8765` |
| Survival | `8766` |
| Peaceful | `8767` |

Не обязательно включать все три сразу. Общего окна на все миры нет: каждый процесс показывает только себя.

Неполный набор (`FC_ADMIN_PORT` без обоих id или без обоих хэшей) валит старт этого процесса. Слушатель на публичном адресе при этом не появляется. Если порт занят, процесс тоже не стартует и не пишет новый снимок мира из-за этой ошибки.

После правки env:

```bash
sudo systemctl restart frontier-cubes-anarchy
```

В журнале будет `admin http: 127.0.0.1:8765`. Токена и хэша в этой строке нет.

## 5. SSH-туннель с Windows

PowerShell. Подставьте своего пользователя, хост VPS и тот порт, который записан в env. Пример для Anarchy:

```powershell
ssh -N -L 127.0.0.1:8765:127.0.0.1:8765 frontier-cubes@VPS_HOST
```

Окно не закрывать. Коллега открывает свой туннель со своим SSH-доступом. Туннель сам по себе не выбирает, кто администратор: дальше нужен личный токен.

Survival и Peaceful — те же команды с портами `8766` и `8767`.

## 6. Вход и `/me` без панели

Панели ещё нет. Проверка из второго окна PowerShell, пока туннель открыт:

```powershell
$secret = Read-Host "Admin token"
$login = Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8765/admin/api/login -ContentType "application/json" -Body (@{ secret = $secret } | ConvertTo-Json) -SessionVariable admin
$login
Invoke-RestMethod -Uri http://127.0.0.1:8765/admin/api/me -WebSession $admin
```

Ответ содержит `adminId` того человека, чей токен ввели, срок сессии и `csrfToken`. Поле `adminId` в теле запроса игнорируется. Сессия живёт в cookie `fc_admin_session`: `HttpOnly`, `SameSite=Strict`, путь `/admin`. По localhost через туннель cookie без флага `Secure`, потому что канал до VPS шифрует SSH, а слушатель остаётся на loopback. На публичный адрес слушатель не переносится.

Чужой токен, ник и игровой `sessionToken` дают одну и ту же ошибку входа. После нескольких неудачных попыток вход на время отвечает «too many attempts».

Смотр игрока, если известен его id:

```powershell
Invoke-RestMethod -Uri http://127.0.0.1:8765/admin/api/player/PLAYER_ID -WebSession $admin
```

Это тот же read-only снимок, что у `AdminInspectionService`. В нём нет игрового `sessionToken` и нет строки базы.

## 7. Выход

```powershell
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8765/admin/api/logout -WebSession $admin -Headers @{
  Origin = "http://127.0.0.1:8765"
  "X-CSRF-Token" = $login.csrfToken
}
```

Без `Origin` и без `X-CSRF-Token` выход не выполняется. Старый cookie после выхода не работает. Простой неактивности — 30 минут. Абсолютный срок сессии — 8 часов. Рестарт процесса забывает все сессии: войти нужно снова.

## 8. Отозвать доступ

Рестарт процесса сразу гасит текущие сессии обоих. Чтобы отозвать именно утёкший токен, замените хэш этого человека по шагу 9. Второй администратор при этом менять токен не обязан.

## 9. Потерянный токен

Снова запустите скрипт, но в env замените только одну половину `FC_ADMIN_AUTH_HASHES`: id остаётся, хэш становится новым. Второй id и его хэш не трогайте. Перезапустите процесс. Старый токен больше не подходит. Новые сессии оба получат только после входа. Самостоятельной регистрации и письма для сброса нет. Третьего администратора эта схема не добавляет.

## 10. Выключить админский HTTP

Закомментируйте или удалите `FC_ADMIN_PORT` и перезапустите процесс. Хэши можно оставить в приватном env: без порта слушатель не создаётся. Игровой `/status` и WebSocket не меняются.

## 11. Ник и `/op` — не вход в админку

Игрок может назваться так же, как id администратора, если ник проходит обычные правила (латиница и цифры, 2–13 символов). Это обычный игрок. Его `sessionToken` к `/admin/api/me` не подходит. `/op` и `FC_OPERATORS` по-прежнему только игровые операторы. Их этот этап не меняет.

## 12. Почему порт нельзя публиковать

Слушатель проверяет `Host` и принимает только `127.0.0.1` и `localhost` на своём порте. Это защита от чужого Host, а не от прямого доступа из интернета. Если пробросить `8765` наружу, токены можно перебирать снаружи. Файрвол этот порт не открывает. Доступ только через SSH-туннель на `127.0.0.1`.

Заголовки `X-Forwarded-Host` и `X-Forwarded-For` личность и хост не выбирают.
