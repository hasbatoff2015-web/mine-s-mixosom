# Закрытый доступ двух администраторов

Игровой сервер и админка — разные входы. Ник, `/op`, `FC_OPERATORS` и игровой `sessionToken` администратором не делают. Права у двух человек одинаковые. Секреты разные. Кто именно вошёл, видно по его id.

Админский HTTP не висит на публичном порте игры. Отдельный слушатель в том же процессе принимает соединения только с `127.0.0.1`. Снаружи его не открывают. Заход с компьютера администратора — SSH-туннель на этот loopback.

Пока `FC_ADMIN_PORT` не задан, слушателя нет. Игра стартует как раньше.

## 1. `FC_ADMIN_IDS`

Ровно два разных id, через запятую. Это не пароли и не ники игроков.

```bash
FC_ADMIN_IDS=admin-owner,admin-colleague
```

Пустое или отсутствующее значение выключает админские действия. Один id, три id, повтор и пробел в id сервер не примет. Оба id имеют одинаковые права. Отдельного суперадмина нет.

## 2. Два секрета

На своём компьютере, не на игровом сервере и не в репозитории:

```bash
npm run admin:provision -- admin-owner admin-colleague
```

Скрипт печатает два случайных токена по 32 байта и строку `FC_ADMIN_AUTH_HASHES`. Файл он не пишет.

Токен владельца передайте только владельцу. Токен коллеги — только коллеге. Устно, через менеджер паролей или другой закрытый канал. В чат, в git и в сейв мира их не кладут. В обычный лог сервера они не попадают.

## 3. Хэши на сервере

В приватный env процесса, например `/etc/frontier-cubes/anarchy.env`, попадают только хэши:

```bash
FC_ADMIN_IDS=admin-owner,admin-colleague
FC_ADMIN_AUTH_HASHES=admin-owner:<64 hex>,admin-colleague:<64 hex>
```

Подставьте строку из вывода скрипта. Сами токены в env не пишите. В git эта строка не коммитится. Шаблоны в `deploy/systemd/*.env` оставляют эти переменные закомментированными.

Хэш пустой строки сервер отвергает. Два одинаковых хэша тоже. Если хэша нет хотя бы у одного id, админский порт не поднимется.

## 4. Приватный порт

```bash
FC_ADMIN_PORT=8765
```

Слушатель всегда на `127.0.0.1`, даже если игровой `HOST=0.0.0.0`. Порт в файрволе не открывать.

Три режима — три процесса. Каждому свой порт, если админка нужна на этом процессе:

| Процесс | Пример порта |
| --- | --- |
| Anarchy | `8765` |
| Survival | `8766` |
| Peaceful | `8767` |

Не обязательно включать все три сразу. Общего окна на все миры нет: каждый процесс показывает только себя.

Неполный набор (`FC_ADMIN_PORT` без обоих id или без обоих хэшей) валит старт этого процесса. Слушатель на публичном адресе при этом не появляется. Если порт занят, процесс тоже не стартует и не пишет новый снимок мира из-за этой ошибки.

После правки env:

```bash
sudo systemctl restart frontier-cubes-anarchy
```

В журнале будет `admin http: 127.0.0.1:8765`. Токена и хэша в этой строке нет.

## 5. SSH-туннель с Windows

PowerShell. Подставьте своего пользователя, хост VPS и тот порт, который записан в env. Пример для Anarchy:

```powershell
ssh -N -L 127.0.0.1:8765:127.0.0.1:8765 frontier-cubes@VPS_HOST
```

Окно не закрывать. Коллега открывает свой туннель со своим SSH-доступом. Туннель сам по себе не выбирает, кто администратор: дальше нужен личный токен.

Survival и Peaceful — те же команды с портами `8766` и `8767`.

## 6. Сборка панели

Панель — отдельная страница, её не кладут в игровой клиент. Перед включением `FC_ADMIN_PORT` соберите её из корня репозитория:

```bash
npm run build:server
npm run build:admin
```

`npm run build` очищает весь `dist`, поэтому панель собирают после него. В `dist/admin` оказываются `index.html`, скрипт, стили, четыре файла шрифтов и значок. Исходных карт нет. `npm run pack:release` копирует `dist/admin` в выпуск вместе с `dist/server`. Если каталога нет, процесс с заданным `FC_ADMIN_PORT` не стартует и не подменяет панель публичным игровым сервером.

## 7. Вход в панель

Туннель из шага 5 должен быть открыт. В браузере на своём компьютере откройте адрес того процесса, который нужен:

| Процесс | Адрес |
| --- | --- |
| Anarchy | `http://127.0.0.1:8765/admin/` |
| Survival | `http://127.0.0.1:8766/admin/` |
| Peaceful | `http://127.0.0.1:8767/admin/` |

Порты — те, что записаны в env. Общего окна на три мира нет: каждая панель показывает только свой процесс и свою экономику.

На странице заголовок «МЕГАКРАФТ ОНЛАЙН», подпись «Панель администратора» и поле «Секретный ключ». Имя администратора выбирать не нужно: сервер узнаёт человека по токену. Токен в адрес, в `localStorage` и в журнал не пишется. После входа страница берёт `adminId` из `GET /admin/api/me`.

Оба администратора видят одни и те же разделы: Игроки, Экономика, Антидюп, Журнал, Сервер, Выход.

## 8. Игроки

Список ищет по нику или по `playerId`. Одинаковые ники — разные строки. Карточка игрока показывает полный id, сеть, режим, здоровье и координаты, если человек в сети, баланс и краткий инвентарь. Игровой `sessionToken` в ответ не входит.

«Кикнуть» сначала записывает решение и журнал в PostgreSQL. Соединение закрывается только после коммита и только если это всё ещё то же соединение, которое видели в момент решения. Если база отказала, игрок остаётся в сети. Повтор того же запроса новое соединение не закрывает.

«Бан по playerId» хранится в PostgreSQL, таблица `admin_player_bans`, вместе со строкой журнала в одной транзакции. После коммита процесс обновляет память из базы, а не из старого ответа. Рестарт читает бан до того, как мир станет готов принимать игроков. Если эту загрузку сделать не удалось, процесс не объявляет мир готовым и не подставляет пустой список.

Старый файл `plugin-data/admin-bans.json` не удаляется. При старте с PostgreSQL id из него добавляются, только если в базе ещё нет строки на этот id. Уже снятый в базе бан файл заново не включает. Правка бана через панель файл сам не переписывает.

Снять бан — отдельный запрос. Повтор старого запроса на бан после более нового снятия игрока снова не банит. Повтор старого снятия после более нового бана бан не снимает. Два администратора сериализуются строкой игрока в базе: в памяти остаётся то, что реально закоммичено.

Это не бан по нику и не бан по IP. Новый независимый `sessionToken` получает новый `playerId` и этим баном не покрывается: отдельных аккаунтов в игре нет.

Без PostgreSQL кик и бан из панели не выполняются. В этом режиме по-прежнему читается только JSON-файл, если он уже был, и он сам не стирается.

Баланс: пустое поле и пробелы не превращаются в ноль. Ноль можно поставить, если ввести `0` и подтвердить. Подтверждение показывает текущий баланс, новый и разницу. Если ответ потерялся, повтор идёт с тем же `requestId`.

Вкладка «Сервер» раз в 15 секунд обновляет только свои строки, пока вкладка открыта и страница видна. Шапка и меню от этого не пропадают.

## 9. Экономика

Баланс и история читаются из книги Мегакоинов этого режима. Anarchy, Survival и Peaceful не складываются.

«Установить баланс» задаёт точное целое число от 0 до максимума. Причина обязательна, она пишется в журнал. В книге Мегакоинов строка имеет тип `ADMIN_SET`. Повтор того же запроса деньги второй раз не двигает: правка и запись журнала проходят одной транзакцией PostgreSQL. Если база отказала, панель не пишет, что правка прошла.

## 10. Антидюп

Раздел показывает уже записанные инциденты уникальных предметов и последнюю книгу учёта пяти ресурсов: алмаз, золотой слиток, рубиновый слиток, титановый слиток, железо. Обычное открытие вкладки мир заново не сканирует.

Расхождение само по себе не означает обман. Статусы различают подтверждённый конфликт, необъяснённый рост, неполное покрытие и уже закрытый случай. Известные пробелы учёта показаны текстом. Кнопка «Проверить сейчас» запускает один ограниченный просмотр и не чаще одного раза в 15 секунд. Предметы и монеты она не забирает и никого не банит.

## 11. Журнал и сервер

Журнал — последние действия администраторов этого развёртывания: кто, что, по кому, причина, время, успех или ошибка. Чужое развёртывание в эту выборку не попадает. Обычное обновление экрана журнал не пополняет.

«Сервер» показывает режим, мир, число людей, заданный тикрейт и измеренное время тика, если тик уже был. Если измерения нет, написано «Нет данных». Заданный 20 TPS сам по себе измеренным не считается. Строки подключения к базе нет. Кнопки рестарта и консоли нет.

## 12. Выход и конец сессии

«Выход» гасит сессию. Нужны cookie и CSRF, их подставляет страница. Простой 30 минут или абсолютные 8 часов дают «Сессия завершена. Войдите снова.» Рестарт процесса забывает сессии обоих.

Проверка без браузера, из второго окна PowerShell, пока туннель открыт:

```powershell
$secret = Read-Host "Admin token"
$login = Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8765/admin/api/login -ContentType "application/json" -Body (@{ secret = $secret } | ConvertTo-Json) -SessionVariable admin
$login
Invoke-RestMethod -Uri http://127.0.0.1:8765/admin/api/me -WebSession $admin
```

Ответ содержит `adminId` того человека, чей токен ввели, срок сессии и `csrfToken`. Поле `adminId` в теле запроса игнорируется. Сессия живёт в cookie `fc_admin_session`: `HttpOnly`, `SameSite=Strict`, путь `/admin`. По localhost через туннель cookie без флага `Secure`, потому что канал до VPS шифрует SSH, а слушатель остаётся на loopback. На публичный адрес слушатель не переносится.

Чужой токен, ник и игровой `sessionToken` дают одну и ту же ошибку входа. После нескольких неудачных попыток вход на время отвечает «too many attempts».

Смотр игрока, если известен его id:

```powershell
Invoke-RestMethod -Uri http://127.0.0.1:8765/admin/api/player/PLAYER_ID -WebSession $admin
```

Это тот же read-only снимок, что у `AdminInspectionService`. В нём нет игрового `sessionToken` и нет строки базы.

## 13. Выход из API

```powershell
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8765/admin/api/logout -WebSession $admin -Headers @{
  Origin = "http://127.0.0.1:8765"
  "X-CSRF-Token" = $login.csrfToken
}
```

Без `Origin` и без `X-CSRF-Token` выход не выполняется. Старый cookie после выхода не работает. Простой неактивности — 30 минут. Абсолютный срок сессии — 8 часов. Рестарт процесса забывает все сессии: войти нужно снова.

## 14. Отозвать доступ

Рестарт процесса сразу гасит текущие сессии обоих. Чтобы отозвать именно утёкший токен, замените хэш этого человека, как в разделе про потерянный токен. Второй администратор при этом менять токен не обязан.

## 15. Потерянный токен

Снова запустите скрипт, но в env замените только одну половину `FC_ADMIN_AUTH_HASHES`: id остаётся, хэш становится новым. Второй id и его хэш не трогайте. Перезапустите процесс. Старый токен больше не подходит. Новые сессии оба получат только после входа. Самостоятельной регистрации и письма для сброса нет. Третьего администратора эта схема не добавляет.

## 16. Выключить админский HTTP

Закомментируйте или удалите `FC_ADMIN_PORT` и перезапустите процесс. Хэши можно оставить в приватном env: без порта слушатель не создаётся. Игровой `/status` и WebSocket не меняются.

## 17. Ник и `/op` — не вход в админку

Игрок может назваться так же, как id администратора, если ник проходит обычные правила (латиница и цифры, 2–13 символов). Это обычный игрок. Его `sessionToken` к `/admin/api/me` не подходит. `/op` и `FC_OPERATORS` по-прежнему только игровые операторы и к закрытому HTTP не относятся. Игровой `/op` тоже не смотрит на ник: право висит на `playerId`. Как выдать его и что делать со старым `permissions.json`: `docs/PERMISSIONS.md`.

## 18. Почему порт нельзя публиковать

Игровой порт по-прежнему отдаёт только `/status` и WebSocket. Страница `/admin/`, её скрипт и `/admin/api` есть только на loopback-слушателе. Вынести этот порт в интернет значит отдать перебор токена и саму панель наружу. Туннель SSH этого не делает: браузер говорит с `127.0.0.1` на вашем компьютере, а SSH доносит это до loopback VPS.

Слушатель проверяет `Host` и принимает только `127.0.0.1` и `localhost` на своём порте. Это защита от чужого Host, а не от прямого доступа из интернета. Если пробросить `8765` наружу, токены можно перебирать снаружи. Файрвол этот порт не открывает. Доступ только через SSH-туннель на `127.0.0.1`.

Заголовки `X-Forwarded-Host` и `X-Forwarded-For` личность и хост не выбирают.
