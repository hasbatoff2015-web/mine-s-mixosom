# Stage A: отмена входа, срок статуса и отдельные ключи гостя

Дата: 2026-10-15

## Goal

Довести гостевой вход так, чтобы отмена, зависший `/status`, вторая вкладка и перенос старого ключа не создавали замену UUID.

## Result

Незаконченное `connect()` завершается один раз: отменой, ошибкой или таймаутом. `GET /status` ждёт не больше 3 секунд. Ключ каждого мира пишется в свой `fc.guest.v2/...`. Старый `fc.guest.v1` и `sessionStorage` читаются и сами не стираются пачкой. Две реальные `AnarchyClient` на одном замке получают один UUID.

## Implemented

- Попытка подключения владеет сигналом, сокетом, таймером и одним завершением промиса.
- Отмена до сокета, во время открытия и после `join` закрывает сокет и не пишет ключ. Позднее приветствие старой попытки новый вход не меняет.
- Уже принятое приветствие обычный выход не превращает в отмену.
- Статус: один запрос, 3000 мс. Таймаут и отмена различаются. Игнор `AbortSignal` у `fetch` промис всё равно завершает.
- Хранилище: `fc.guest.v2/<deployment>/<mode>/<world>`, части через `encodeURIComponent`.
- Перенос: v2, иначе слот в v1, иначе один старый ключ `sessionStorage`. После приветствия пишется тот же ключ в v2. v1 не удаляется.
- Под замком хранилище читается снова. Битая, неизвестная или недоступная запись новую регистрацию не разрешает.
- Замок держится до записи ключа после приветствия и отпускается при отмене.

## Architecture decisions

Отдельный ключ на слот убирает гонку read-modify-write общего JSON между режимами. Общий замок на все записи не вводился: Web Locks есть не везде, а разные слоты и так не делят документ.

Замок первой регистрации держится до подтверждённой записи ключа, чтобы вторая вкладка прочитала уже записанный токен. Это не транзакция с `players.json`.

## Tests

Клиентские тесты гоняют `AnarchyClient.connect()` на поддельном `WebSocket` и поддельном `fetch`. Это не сетевой интеграционный тест и не запись `players.json`.

Серверные тесты личности в этом проходе не переписывались: граница «сначала запись, потом приветствие» не менялась.

## Performance

На тике игры новых чтений `localStorage`, замков и запросов статуса нет. Работа только вокруг входа: один статус, несколько чтений, одна запись после приветствия, замок только на первую регистрацию слота.

## Known issues

Если сервер уже записал нового гостя, а браузер не сохранил ключ, вторая вкладка этот UUID сама не найдёт. Откат записи на сервере не делается.

Без Web Locks две одновременные первые регистрации одного слота по-прежнему не сериализуются.
