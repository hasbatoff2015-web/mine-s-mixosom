# Armor HUD and canonical armor points

## Goal

Add a Minecraft-like armor bar to the player HUD and keep a single canonical armor total for both damage and UI. Do not add new armor sets. Do not change Fire/Lava armor mitigation.

## Result

Implemented on `cursor/fluids-and-items-pass-935a` from accepted potion-pass HEAD `c9561bc`. Draft PR #6 stays draft. `main` was not merged. No force push.

Existing leather / gold / iron / diamond **defense values already matched** Java 1.9. They were not rewritten.

Individual pieces already matched the requested table, including Iron 2/6/5/2.

## Armor Scale

- `MAX_ARMOR_POINTS = 20`
- 10 icons; full = 2 points; half = 1 point
- HUD `clamp(total, 0, 20)` via the same helper as damage

## HUD

- Location: `#status-bars .status-left`, **above hearts**, same container as health/hunger so it tracks the HUD, not a separate viewport corner
- Hidden when armor is 0; 10 icons including empty outlines when armor > 0
- Sprites: generated 9×9 pixel-art chestplates `public/textures/gui/armor_{empty,half,full}.png` (`image-rendering: pixelated`). Pack has no `gui/icons.png` in the runtime whitelist.
- Update path: `Game.refreshHud()` already runs on inventory `onChanged` and every 2 ticks, now passing `armor: getArmorPoints(session.inventory)`

## Canonical Armor Integration

- `getArmorStats(source)` remains the equipment/stat reader
- **`getArmorPoints(source)`** is the single total (`stats.points`)
- HUD calls `armorHudIcons(getArmorPoints(inventory))` — no second sum
- Damage `reduceDamageByArmor` still uses `getArmorStats`

## Damage Regression

`ARMOR_BYPASS_SOURCES` is still fall / drowning / starvation / suffocation / void. Fire and Lava go through armor. Targeted test: full iron (15) reduces both Fire and Lava vs bare; `reduceDamageByArmor(10, inventory)` equals `reduceDamageByArmor(10, { points: 15 })`.

## Tests

Targeted `tests/armor-hud.test.ts` (7): piece table, full sets, mixed 15, HUD mapping, clamp, Fire/Lava via the same total.

`npm run check` pieces: typecheck PASS; vitest **59 files, 542 tests**; production **120 modules**, **1.16 MiB / 183 files** (three 9×9 armor sprites). One unrelated mob-separation assertion flaked once under full parallel load and passed on rerun; not touched in this pass.

## Manual QA

A. EMPTY: no armor → bar hidden  
B. ONE PIECE: helmet/chest/etc → correct full/half count  
C. FULL IRON: 15 → 7 full + 1 half  
D. FULL DIAMOND: 20 → 10 full  
E. MIXED: sum of equipped pieces  
F. REMOVE: bar updates immediately  
G. FIRE/LAVA: with armor less damage than without
