# Гостевая личность игрока

`playerId` — это UUID, который выдаёт сервер и хранит в мире. Ник к нему не привязан. Два игрока с одним ником — два разных персонажа.

Гостевой ключ — секрет, который сервер выдаёт вместе с `playerId`. Браузер хранит ключ и при следующем входе отдаёт его серверу. Сервер по ключу находит ту же запись. Ключ нельзя угадать по нику.

## Где лежит ключ

В `localStorage` страница хранит запись `fc.guest.v1`. Внутри отдельные слоты:

`развёртывание|режим|id мира`

Развёртывание берётся с адреса страницы, не с адреса WebSocket:

- `127.0.0.1` и `localhost` — `local`
- `dev.megacraft.agariobrainrot.ru` — `dev`
- `megacraft.agariobrainrot.ru` — `prod`
- любой другой сайт — свой слот, не общий с dev или prod

Режим — `anarchy`, `survival` или `peaceful`. Id мира — поле `world` из `GET /status`. Это имя каталога под `WORLD_PATH`, а не адрес сокета.

Старые ключи `fc.anarchy.sessionToken` и `fc.session.<адрес сокета>` ещё читаются. После успешного входа тот же ключ переносится в `fc.guest.v1`, и только тогда старая копия удаляется. Если подтверждения нет, старый ключ остаётся.

Смена доверенного адреса WebSocket при том же сайте, режиме и мире персонажа не сбрасывает. Смена `WORLD` — это другой слот. Старый ключ не отправляется в новый мир и не затирается.

Параметры `?anarchyUrl=`, `?anarchyHost=` и `?anarchyPort=` , если они уводят сокет с обычного адреса, сохранённый ключ не получают.

Если браузер запрещает `localStorage`, игра может войти, но предупреждает, что после закрытия браузера персонаж может не восстановиться.

## Что делает сервер

Новый гость без ключа получает новый UUID. Запись в `players.json` пишется до приветствия. Если запись не удалась, приветствия нет и новый персонаж в мир не публикуется.

Известный ключ возвращает тот же UUID, инвентарь и связи по этому id: OP, дома, друзья, приваты, экономика.

Неизвестный ключ не создаёт замену. Сервер отвечает `unknown_guest`. Браузер ключ не стирает. Новый гость создаётся только после явного подтверждения в окне. Прежний ключ остаётся в поле `retained` и сам больше не отправляется.

Ник не выдаёт OP, дом или чужой инвентарь.

Обычный перезапуск процесса читает `players.json`. Каталог мира — `WORLD_PATH`/`WORLD`. Скрипты выкладки в этом репозитории `WORLD` не меняют. Команда `dev-switch` в репозитории нет: если на DEV имя мира меняется между ветками, это делает внешний скрипт. Проверка без изменения файлов:

```bash
systemctl show frontier-cubes-anarchy -p Environment
# или для DEV-процесса, если unit другой:
# systemctl cat <dev-unit>
curl -sS http://127.0.0.1:2667/status
```

В ответе `/status` поля `mode` и `world` должны совпасть с ожидаемым миром. `ready` должен быть `true`.

## Если ключ в браузере потерян

Сервер по-прежнему хранит оба UUID, даже если ники совпали. Сам он их не сливает и деньги не складывает.

Осмотр мира, пока процесс остановлен:

```bash
node scripts/recover-guest.mjs inspect --world /путь/к/каталогу/мира
```

В выводе есть `playerId`, ник, `updatedAt` и число занятых слотов. Секретного ключа там нет.

Смена ключа у выбранного UUID, по умолчанию без записи:

```bash
node scripts/recover-guest.mjs rotate --world /путь/к/каталогу/мира --player <uuid>
node scripts/recover-guest.mjs rotate --world /путь/к/каталогу/мира --player <uuid> --apply
```

`--apply` копирует `players.json` рядом в `players.json.recover-backup-<время>`, пишет новый ключ атомарно и печатает одну строку `recovery-token:`. UUID не меняется. Другие игроки не трогаются. Если в каталоге есть `.instance.lock`, команда отказывается: сначала остановите процесс мира.

Строку `recovery-token` не вставляйте в публичный чат и не кладите в git. На нужном сайте, в консоли браузера, её можно записать только в слот этого развёртывания и мира. Пример формы, без настоящего ключа:

```js
localStorage.setItem('fc.guest.v1', JSON.stringify({
  version: 1,
  records: {
    'dev|anarchy|ИМЯ_МИРА': { sessionToken: 'ВСТАВИТЬ_КЛЮЧ_ЛОКАЛЬНО' },
  },
}));
```

После входа проверьте OP командой, которая смотрит id, а не ник. Чужой UUID права не получит.

Другое устройство без привязки Яндекса тот же гостевой ключ само не увидит. Привязка аккаунта Яндекса в этот шаг не входит: внутренний `playerId` для неё сохраняется.

## Перед восстановлением

Снимите копию каталога мира или дождитесь `fc-backup`, если это VPS. Не копируйте один мир поверх другого и не меняйте живой `WORLD` ради «склейки» персонажей.
