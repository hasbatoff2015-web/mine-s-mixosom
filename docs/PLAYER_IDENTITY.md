# Гостевая личность игрока

`playerId` — это UUID, который выдаёт сервер и хранит в мире. Ник к нему не привязан. Два игрока с одним ником — два разных персонажа.

Гостевой ключ — секрет, который сервер выдаёт вместе с `playerId`. Браузер хранит ключ и при следующем входе отдаёт его серверу. Сервер по ключу находит ту же запись. Ключ нельзя угадать по нику.

## Где лежит ключ

Каждый слот — отдельный ключ `localStorage`:

`fc.guest.v2/<развёртывание>/<режим>/<id мира>`

Части адреса кодируются через `encodeURIComponent`, поэтому значения с `/` и `%` не слипаются. В значении JSON версии 2: `sessionToken` и, если ключ меняли, `retained`.

Развёртывание берётся с адреса страницы, не с адреса WebSocket:

- `127.0.0.1` и `localhost` — `local`
- `dev.megacraft.agariobrainrot.ru` — `dev`
- `megacraft.agariobrainrot.ru` — `prod`
- любой другой сайт — свой слот, не общий с dev или prod

Режим — `anarchy`, `survival` или `peaceful`. Id мира — поле `world` из `GET /status`. Это имя каталога под `WORLD_PATH`, а не адрес сокета.

Старый общий документ `fc.guest.v1` больше не переписывается. Если для этого слота ещё нет записи v2, игра читает оттуда прежний ключ. После успешного входа тот же ключ записывается в свой ключ v2. Остальные слоты в v1 остаются, пока их не откроют отдельно. Документ v1 сам не удаляется.

Если для одного слота есть и v2, и v1, игра отправляет только v2. Ключ из v1 не стирается и с v2 не сливается.

Старые ключи `fc.anarchy.sessionToken` и `fc.session.<адрес сокета>` ещё читаются, если нет ни v2, ни слота в v1. После успешного входа тот же ключ пишется в v2, и только тогда старая копия из `sessionStorage` удаляется. Если подтверждения нет, старая копия остаётся.

Карточка в меню выбирает режим. Survival спрашивает статус Survival, а не Anarchy. Ключ Anarchy в Survival не уходит. Другой режим — отдельный ключ, это не смена мира. Запись Anarchy не переписывает ключ Survival: это разные ключи `localStorage`.

Смена доверенного адреса WebSocket при том же сайте, режиме и мире персонажа не сбрасывает. Смена `WORLD` внутри того же режима — другой мир: старый ключ не отправляется, новый персонаж сам не создаётся, пока игрок явно не подтвердит отдельного гостя. Это верно и когда прежний мир лежит только в `fc.guest.v1`. Отмена ничего не пишет.

Подтверждение нового гостя относится только к одному сайту, режиму и id мира и только к тому ключу, который браузер уже видел. Оно не записывается в `localStorage` и на сервер не уходит. Пока вкладка ждёт замок, другая вкладка может успеть сохранить новый ключ этого же мира: тогда подтверждение его не затирает, вход идёт этим новым ключом. Если за это время `/status` открыл другой мир или другой режим, старое подтверждение не действует, нужно согласие ещё раз. Отказ в окне повторный вход не начинает.

Чтобы решить, есть ли другой мир того же режима, браузер перечисляет ключи `fc.guest.v2/`. Если список прочитать нельзя, это не пустой список: новый персонаж сам не создаётся, сокет не открывается, уже лежащие ключи не стираются. Уже прочитанный ключ текущего мира при этом по-прежнему отправляется. Если перечисление сломалось, не чистите хранилище скриптом. Проверьте, что сайт может читать `localStorage`, и войдите снова. Если свой ключ на месте, персонаж вернётся. Если нет — восстановите один слот, как в разделе ниже.

Сокет получает сохранённый ключ только если его адрес совпадает с обычным адресом выбранной карточки. Чужой `?anarchyUrl=`, `?anarchyHost=` или `?anarchyPort=` ключ не получает. Приветствие с другим `worldId`, чем у проверенного статуса, в `localStorage` не пишется. Отменённая попытка и опоздавшее приветствие ключ не пишут.

Проверка `GET /status` ждёт не дольше 3 секунд. Если ответа нет, игра сообщает об этом и сокет не открывает. Новый персонаж из-за тишины статуса не создаётся. Отмена до этого срока — это отмена, а не таймаут.

Если браузер не смог прочитать хранилище, новый персонаж сам не создаётся. Можно явно продолжить без сохранения: старая запись не стирается, и игра не обещает, что персонаж вернётся. Повреждённая или неизвестной версии запись v2 этого слота не затирается и не считается пустым аккаунтом. Если v2 для слота нет, а весь `fc.guest.v1` повреждён или неизвестной версии, новый персонаж тоже не создаётся и документ v1 не переписывается. Исправная запись v2 при этом читается, даже если старый документ v1 сломан.

Пока вкладка впервые регистрирует гостя, она держит Web Lock `fc-guest:<развёртывание>|<режим>|<мир>` до записи ключа. Вторая вкладка ждёт, перечитывает хранилище и входит тем же ключом. Если за время ожидания запись стала битой, неизвестной версии или недоступной, вторая вкладка нового UUID не создаёт. Отмена снимает ожидание и отпускает замок. Без Web Locks обычный вход работает, но две одновременные первые регистрации одного слота атомарно не сериализуются. Замок на время игры не держится.

Отмена подключения завершает его обещание. Это касается ожидания статуса, открытия сокета и ожидания приветствия. Уже принятое приветствие позже отмена не отменяет: выход из игры — отдельный шаг, ключ остаётся.

Если браузер запрещает `localStorage`, игра может войти, но предупреждает, что после закрытия браузера персонаж может не восстановиться.

## Что делает сервер

Новый гость без ключа получает новый UUID. Запись в `players.json` пишется до приветствия. Если запись не удалась, приветствия нет и новый персонаж в мир не публикуется. Если сервер уже записал персонажа, а браузер не успел сохранить ключ, это не одна транзакция: UUID на сервере остаётся, а следующая вкладка может не увидеть ключ. Игра тогда не обещает, что вход был сохранён.

Известный ключ возвращает тот же UUID, инвентарь и связи по этому id: OP, дома, друзья, приваты, экономика.

Неизвестный ключ не создаёт замену. Сервер отвечает `unknown_guest`. Браузер ключ не стирает и не отправляет его снова после согласия. Новый гость создаётся только после явного подтверждения в окне для этого мира: в пакете входа `freshGuest` без старого ключа. Прежний ключ остаётся в поле `retained` и сам больше не отправляется. Запись игрока на сервере при этом не меняется.

Ник не выдаёт OP, дом или чужой инвентарь.

Обычный перезапуск процесса читает `players.json`. Каталог мира — `WORLD_PATH`/`WORLD`. Скрипты выкладки в этом репозитории `WORLD` не меняют. Команда `dev-switch` в репозитории нет: если на DEV имя мира меняется между ветками, это делает внешний скрипт. Проверка без изменения файлов:

```bash
systemctl show frontier-cubes-anarchy -p Environment
# или для DEV-процесса, если unit другой:
# systemctl cat <dev-unit>
curl -sS http://127.0.0.1:2667/status
```

В ответе `/status` поля `mode` и `world` должны совпасть с ожидаемым миром. `ready` должен быть `true`.

## Если ключ в браузере потерян

Сервер по-прежнему хранит оба UUID, даже если ники совпали. Сам он их не сливает и деньги не складывает.

Осмотр мира, пока процесс остановлен:

```bash
node scripts/recover-guest.mjs inspect --world /путь/к/каталогу/мира
```

В выводе есть `playerId`, ник, `updatedAt` и число занятых слотов. Секретного ключа там нет.

Смена ключа у выбранного UUID, по умолчанию без записи:

```bash
node scripts/recover-guest.mjs rotate --world /путь/к/каталогу/мира --player <uuid>
node scripts/recover-guest.mjs rotate --world /путь/к/каталогу/мира --player <uuid> --apply
```

`--apply` копирует `players.json` рядом в `players.json.recover-backup-<время>`, пишет новый ключ атомарно и печатает одну строку `recovery-token:`. UUID не меняется. Другие игроки не трогаются. Если в каталоге есть `.instance.lock`, команда отказывается: сначала остановите процесс мира.

Строку `recovery-token` не вставляйте в публичный чат и не кладите в git. Не переписывайте `fc.guest.v1` и не стирайте другие ключи `fc.guest.v2/`. На нужном сайте, в консоли, замените только один слот. Если в этом слоте уже лежит сломанный JSON или `version` не 2, остановитесь и не пишите ключ.

```js
const key = 'fc.guest.v2/' + encodeURIComponent('dev') + '/' + encodeURIComponent('anarchy') + '/' + encodeURIComponent('ИМЯ_МИРА');
const token = 'ВСТАВИТЬ_КЛЮЧ_ЛОКАЛЬНО';
const raw = localStorage.getItem(key);
if (raw) {
  let parsed;
  try { parsed = JSON.parse(raw); } catch { throw new Error('слот сломан, не перезаписываем'); }
  if (!parsed || parsed.version !== 2 || typeof parsed.sessionToken !== 'string') {
    throw new Error('слот неизвестен, не перезаписываем');
  }
  if (parsed.sessionToken === token) throw new Error('этот ключ уже записан');
  const retained = [...new Set([...(parsed.retained ?? []), parsed.sessionToken])];
  localStorage.setItem(key, JSON.stringify({ version: 2, sessionToken: token, retained }));
} else {
  localStorage.setItem(key, JSON.stringify({ version: 2, sessionToken: token }));
}
```

После входа проверьте OP командой, которая смотрит id, а не ник. Чужой UUID права не получит.

Другое устройство без привязки Яндекса тот же гостевой ключ само не увидит. Привязка аккаунта Яндекса в этот шаг не входит: внутренний `playerId` для неё сохраняется.

## Перед восстановлением

Снимите копию каталога мира или дождитесь `fc-backup`, если это VPS. Не копируйте один мир поверх другого и не меняйте живой `WORLD` ради «склейки» персонажей.
